## 1. INTRODUCTION
La présente Politique de confidentialité explique comment **LajanAnsanm** collecte, utilise, conserve et protège les données personnelles des personnes qui utilisent sa plateforme.

LajanAnsanm est un projet personnel de plateforme numérique destiné à faciliter l’organisation et le suivi des tontines.

La protection des informations des organisateurs et des membres constitue un élément important du fonctionnement du service.

Cette politique présente :

- les catégories de données susceptibles d’être collectées ;
- les raisons pour lesquelles ces données sont utilisées ;
- les personnes pouvant y accéder ;
- les conditions de conservation ;
- les mesures de sécurité prévues ;
- les moyens de contacter LajanAnsanm pour toute question relative aux données personnelles.
La présente politique concerne les données traitées dans le cadre de l’utilisation de la plateforme. Elle devra être mise à jour si de nouvelles fonctionnalités ou de nouveaux prestataires modifient les traitements réalisés.

## 3. CATÉGORIES DE DONNÉES COLLECTÉES
Les données effectivement collectées dépendent des fonctionnalités activées et utilisées. LajanAnsanm doit limiter leur collecte à ce qui est nécessaire au fonctionnement du service.

### 3.1. Données relatives aux organisateurs
Lorsqu’une personne crée un compte organisateur, la plateforme peut collecter :

- son nom ou nom d’affichage ;
- son adresse électronique ;
- son numéro de téléphone, lorsqu’il est demandé ;
- les informations nécessaires à la connexion et à la vérification du compte ;
- les informations relatives à son abonnement ;
- les données techniques nécessaires à la sécurité du compte.

### 3.2. Données relatives aux membres
Lorsqu’un organisateur ajoute un membre à une tontine, les informations suivantes peuvent être enregistrées :

- le nom du membre ;
- son numéro de téléphone, lorsqu’il est fourni ;
- son identifiant interne dans la tontine ;
- son lien personnel d’accès au portail membre ;
- les informations relatives à sa participation.
L’organisateur doit obtenir le consentement du membre avant de l’ajouter à une tontine et doit l’informer de l’utilisation de ses informations.

### 3.3. Données relatives aux tontines
Pour permettre la gestion des tontines, LajanAnsanm peut traiter :

- le nom de la tontine ;
- le montant des contributions ;
- la fréquence des contributions ;
- les dates prévues ;
- les cycles et les tours ;
- la liste des participants ;
- les bénéficiaires désignés ;
- l’historique des contributions ;
- les statuts de paiement ;
- les déclarations de paiement ;
- les confirmations ou contestations de réception des versements.

### 3.4. Données relatives aux paiements des tontines
LajanAnsanm peut enregistrer les informations nécessaires au suivi administratif des contributions, notamment :

- le montant déclaré ;
- la date de déclaration ;
- le moyen de paiement indiqué ;
- le numéro de transaction lorsqu’il est communiqué ;
- le numéro ou compte émetteur, lorsqu’il est fourni ;
- l’image du reçu ou de la capture d’écran transmise pour justifier le paiement ;
- le statut de la déclaration ;
- la date de validation ou de rejet ;
- les informations nécessaires à l’historique de la tontine.
Ces informations ne signifient pas que LajanAnsanm reçoit ou conserve les fonds destinés aux tontines.

Les contributions sont transférées directement entre les participants, par les moyens qu’ils ont convenus.

### 3.5. Données relatives aux abonnements
Lorsqu’un utilisateur souscrit à un abonnement, la plateforme peut traiter :

- le forfait choisi ;
- le montant de l’abonnement ;
- la date de souscription ;
- la date d’expiration ;
- le statut du paiement ;
- la référence de transaction communiquée par le prestataire ;
- le numéro ou compte émetteur, lorsqu’il est fourni ;
- l’image du reçu ou de la capture d’écran du paiement manuel ;
- les images QR MonCash ou NatCash configurées pour recevoir les paiements ;
- les informations nécessaires à la gestion de l’accès aux fonctionnalités payantes.
Les données de paiement sensibles doivent être traitées selon les modalités du prestataire concerné. LajanAnsanm ne doit pas collecter ou conserver des informations de paiement sensibles lorsqu’elles ne sont pas nécessaires à son fonctionnement.

### 3.6. Données techniques
Dans le cadre de la sécurité et du fonctionnement du service, certaines données techniques peuvent être traitées, selon la configuration réelle de la plateforme :

- informations relatives à la session ;
- date et heure de connexion ;
- informations sur le navigateur ou l’appareil ;
- adresse IP ;
- journaux d’activité et de sécurité ;
- informations relatives aux erreurs techniques.
Les données techniques effectivement enregistrées devront être recensées avant la publication définitive de cette politique.

## 4. FINALITÉS DU TRAITEMENT
Les données collectées peuvent être utilisées pour les finalités suivantes.

### 4.1. Gestion des comptes

- créer et administrer les comptes organisateurs ;
- vérifier les adresses électroniques ;
- permettre l’authentification ;
- gérer les accès ;
- administrer les abonnements.

### 4.2. Gestion des tontines

- créer et configurer les tontines ;
- ajouter les membres ;
- organiser les cycles et les tours ;
- suivre les contributions ;
- identifier les bénéficiaires ;
- consulter l’historique des opérations ;
- produire des rapports.

### 4.3. Gestion des déclarations de paiement

- recevoir les déclarations des membres ;
- transmettre ces déclarations à l’organisateur concerné ;
- enregistrer leur validation ou leur rejet ;
- distinguer les déclarations en attente des contributions validées.
Une déclaration en attente n’est pas comptabilisée comme une contribution confirmée dans les totaux et rapports de la tontine.

### 4.4. Sécurité et prévention des abus
Les données techniques et les informations relatives aux comptes peuvent être utilisées pour :

- protéger les comptes ;
- détecter des activités inhabituelles ;
- prévenir les accès non autorisés ;
- limiter les utilisations abusives ;
- assurer le bon fonctionnement de la plateforme.

### 4.5. Assistance et communication
Les informations de contact peuvent être utilisées pour répondre aux demandes des utilisateurs, transmettre des informations importantes sur le service ou communiquer des changements relatifs à leur compte.

Les communications commerciales éventuelles devront respecter les règles applicables et les choix des utilisateurs.

## 5. BASES ET CONDITIONS DU TRAITEMENT
Les données personnelles doivent être traitées pour des finalités déterminées et légitimes.

Selon la nature du traitement et les règles applicables, leur utilisation peut notamment être nécessaire :

- à la fourniture des fonctionnalités demandées par l’utilisateur ;
- à la gestion du compte et de la tontine ;
- au respect d’une obligation légale ;
- à la sécurité et à la prévention des abus ;
- à la gestion d’une demande ou d’une réclamation ;

Le consentement à l’ajout d’un membre à une tontine doit être recueilli avant l’enregistrement de ses informations par l’organisateur.

Les modalités précises de recueil, de preuve et de retrait du consentement doivent correspondre au fonctionnement réel de l’application.

## 6. ACCÈS AUX DONNÉES
L’accès aux informations dépend du rôle de chaque personne dans la plateforme.

### 6.1. Organisateur
L’organisateur peut accéder aux informations relatives aux tontines qu’il a créées, dans la limite des fonctionnalités et autorisations prévues par la plateforme.

Il peut notamment consulter les informations des membres, les contributions déclarées, les statuts de validation et les historiques nécessaires à la gestion de ses tontines.

Il doit utiliser ces informations uniquement pour les besoins légitimes de la gestion de la tontine et ne pas les communiquer à des personnes non autorisées.

### 6.2. Membre
Le membre accède à son portail personnel au moyen de son lien individuel.

Selon les fonctionnalités disponibles, il peut consulter :

- les informations de sa tontine qui lui sont destinées ;
- le calendrier des contributions ;
- les noms des bénéficiaires ;
- ses propres déclarations et leur statut ;
- les informations relatives à sa participation.
Dans le fonctionnement prévu de la plateforme, un membre ne doit pas pouvoir consulter les numéros de téléphone des autres membres ni les détails individuels de leurs paiements.

### 6.3. Propriétaire de la plateforme
L’interface d’administration permet au propriétaire de consulter les noms et adresses électroniques des organisateurs, la date de création de leur compte, leur dernière activité et le statut de vérification de leur adresse électronique. Elle affiche également des statistiques globales ou par organisateur : nombre de tontines, nombre de membres actifs, volumes de contributions déclarées et historique récent des actions.

Le propriétaire peut aussi consulter et gérer les plans, les abonnements et les demandes de paiement. Une demande de paiement manuel peut inclure le nom et l’adresse électronique de l’organisateur, le numéro ou compte émetteur s’il est fourni, le compte destinataire, la référence de transaction lorsqu’elle est requise, une note et l’image du reçu, qui est obligatoire pour les paiements manuels. Les images QR configurées par le propriétaire pour les abonnements sont également conservées dans le stockage privé. L’interface d’activité affiche l’identité de l’organisateur, l’action, sa date et son adresse IP ; l’adresse IP figure également dans l’export CSV.

L’interface de gestion des comptes n’affiche pas les noms et numéros de téléphone individuels des membres des tontines. Elle affiche des nombres agrégés. Cette limite ne s’applique pas aux informations qu’un organisateur peut consulter pour gérer ses propres tontines. Les accès techniques à la base de données ou à l’infrastructure dépendent de la configuration et des personnes habilitées chez les prestataires.

Ces accès administratifs sont réservés au propriétaire habilité et doivent être utilisés uniquement pour la gestion, la sécurité, l’assistance et le fonctionnement du service.

### 6.4. Prestataires techniques
Le code de l’application permet de configurer des prestataires selon le déploiement. Le dépôt ne permet pas d’identifier à lui seul les prestataires effectivement activés en production. Ceux-ci doivent être recensés et indiqués avant le lancement public. Les catégories prévues comprennent :

- l’hébergement de la plateforme ;
- l’envoi de courriels ;
- le traitement des abonnements en ligne ;
- la maintenance et la sécurité ;
- les services techniques nécessaires au fonctionnement du site.

Par défaut, le stockage des fichiers de l’application est local ; une configuration S3 est également prévue. Les reçus transmis avec les demandes de paiement et les images QR configurées pour les paiements sont enregistrés dans le stockage privé configuré. Le transport des courriels dépend de la configuration du serveur ; le fichier d’exemple utilise le journal local et ne désigne pas un fournisseur de courriel de production.

Les prestataires effectivement utilisés ne doivent recevoir que les informations nécessaires à leurs missions, selon les modalités contractuelles et les règles applicables.

## 7. PARTAGE ET TRANSMISSION DES DONNÉES
LajanAnsanm ne vend pas les données personnelles des utilisateurs.

Les données peuvent être communiquées lorsque cela est nécessaire :

- au fonctionnement de la tontine ;
- à l’exécution d’une demande de l’utilisateur ;
- au fonctionnement d’un service technique ou de paiement ;
- à la sécurité de la plateforme ;
- au respect d’une obligation légale ;
- au traitement d’une réclamation ou d’un différend.
Lorsqu’un prestataire de paiement intervient dans le traitement d’un abonnement, les informations nécessaires peuvent lui être transmises selon son rôle et ses propres conditions de confidentialité.

Les contributions des tontines et les paiements des abonnements LajanAnsanm sont deux opérations distinctes.

Pour les abonnements, l’application accepte des demandes de paiement manuel par QR MonCash ou NatCash, ou par virement bancaire lorsque ces méthodes sont configurées. Le numéro ou compte de l’émetteur est facultatif. Un reçu ou une capture d’écran est obligatoire pour toute demande manuelle ; une référence de transaction est obligatoire pour MonCash et NatCash, mais facultative pour un virement bancaire. Le propriétaire examine la demande depuis l’administration. Un paiement MonCash en ligne par MonCashConnect est aussi prévu, mais n’est disponible que si cette intégration est activée en production.

Les données ne doivent pas être communiquées à un tiers pour une finalité incompatible avec celle pour laquelle elles ont été collectées, sous réserve des cas autorisés par les règles applicables.

## 8. LIENS PERSONNELS DES MEMBRES
Chaque membre peut accéder à son espace au moyen d’un lien personnel.

Ce lien constitue un moyen d’accès à certaines informations relatives à la participation du membre.

Le lien du portail membre n’a pas de date d’expiration automatique dans l’application. Le jeton comporte 40 caractères aléatoires ; l’application conserve son empreinte SHA-256 pour le retrouver ainsi qu’une copie chiffrée pour pouvoir réafficher le lien à l’organisateur. La session ouverte après l’accès au lien est distincte du lien lui-même et peut expirer selon les paramètres de session du déploiement.

Le membre doit :

- conserver ce lien de manière confidentielle ;
- éviter de le publier ou de le transmettre à des personnes non autorisées ;
- informer l’organisateur s’il pense que le lien a été compromis.

L’organisateur peut remplacer le lien depuis les réglages du portail ; l’ancien cesse alors immédiatement de fonctionner. L’accès est également bloqué lorsque le membre est désactivé, que le portail est fermé ou que la tontine est terminée.

Les liens d’invitation à rejoindre une tontine sont différents des liens personnels du portail : une invitation expire après 14 jours, ne peut être acceptée qu’une fois et n’est utilisable que tant que la tontine est en brouillon. Elle peut aussi être révoquée.

## 9. DURÉE DE CONSERVATION
Les données sont conservées pendant la durée nécessaire aux finalités pour lesquelles elles ont été collectées.

Les informations liées à une tontine peuvent être conservées pendant son fonctionnement afin de garantir le suivi des contributions, des cycles, des bénéficiaires et de l’historique collectif.

La fermeture d’un compte ne signifie pas nécessairement la suppression immédiate de toutes les informations liées à une tontine.

Certaines données peuvent être conservées lorsqu’elles sont nécessaires :

- à la conservation de l’historique collectif ;
- à la vérification d’une opération ;
- à la résolution d’un différend ;
- à la sécurité du service ;
- au respect d’une obligation légale applicable.
Les données qui ne sont plus nécessaires doivent être supprimées ou rendues anonymes lorsque cela est possible et approprié.

L’application ne définit actuellement ni calendrier automatique d’effacement ni durée précise de conservation pour les données des membres, les historiques de tontine, les demandes de paiement, les reçus ou les journaux d’activité. Les journaux d’activité applicatifs sont conservés sans date d’expiration définie par l’application. La durée réelle peut aussi dépendre des sauvegardes, journaux et règles de conservation de l’hébergeur.

Lorsqu’un membre ayant un historique de contributions ou de versements est retiré d’une tontine, son compte membre est désactivé plutôt que supprimé afin de préserver cet historique. Un membre sans cet historique peut être supprimé. La suppression d’une tontine ou d’un compte peut entraîner la suppression en base des données qui en dépendent ; les durées applicables aux copies de sauvegarde et aux fichiers reçus doivent être définies séparément.

Les durées précises doivent être fixées avant la mise en production :

| Catégorie de données | Durée de conservation |
|---|---|
| Données des comptes organisateurs | À définir selon la durée du compte et les obligations applicables |
| Données des membres | À définir selon la durée de la tontine et les besoins de son historique |
| Historique des contributions | À définir selon les besoins de preuve et les obligations applicables |
| Références de paiement | À définir selon la finalité et les obligations applicables |
| Journaux de sécurité | À définir selon les besoins de sécurité |
| Données d’abonnement | À définir selon les besoins de gestion et les obligations applicables |

Ces durées ne doivent pas rester indéterminées lors du lancement public. Elles doivent être définies en fonction des finalités réelles, des contraintes techniques et des obligations légales applicables.

## 10. CORRECTION, SUPPRESSION ET FERMETURE
Un utilisateur qui constate une erreur dans ses informations peut demander leur correction.

Pour les données relatives à une tontine, le membre peut contacter l’organisateur afin de demander une vérification ou une correction.

L’organisateur peut retirer un membre d’une tontine selon les règles de fonctionnement de la plateforme.

Toutefois, le retrait d’un membre ne signifie pas nécessairement que toutes les données historiques le concernant seront immédiatement supprimées.

Les informations nécessaires à la cohérence de l’historique collectif, à la preuve d’une opération ou au respect d’une obligation applicable peuvent être conservées pendant la durée nécessaire.

L’organisateur peut demander la fermeture de son compte depuis les paramètres de son profil lorsque cette fonction est disponible et que les conditions de fermeture sont remplies.

Les demandes portant sur les données personnelles peuvent être adressées à :

[**lajanansanm.ht@gmail.com**](mailto:lajanansanm.ht@gmail.com)

Chaque demande sera examinée selon les règles applicables et les contraintes légitimes de conservation.

## 11. SÉCURITÉ DES DONNÉES
LajanAnsanm prévoit de mettre en place des mesures techniques et organisationnelles raisonnables pour protéger les informations traitées.

Ces mesures peuvent notamment comprendre :

- l’authentification des utilisateurs ;
- la gestion des autorisations selon les rôles ;
- la protection des liens d’accès aux portails membres ;
- la limitation des accès administratifs ;
- la protection des échanges de données ;
- la sauvegarde des informations ;
- la surveillance des activités inhabituelles ;
- les mises à jour de sécurité ;

Les mesures décrites doivent être vérifiées par rapport à la configuration réellement déployée. La présente politique ne doit pas être interprétée comme une certification de sécurité.

En cas d’incident affectant les données personnelles, LajanAnsanm prendra les mesures raisonnables pour limiter les conséquences et appliquera les obligations de notification prévues par les règles applicables.
